# 05 RMSNorm：大模型里最常见的归一化

代码：`src/rmsnorm.cu`。8192 行（token）× 4096 维（hidden）。

公式：y = x / √(mean(x²) + ε) · w。和 LayerNorm 相比，它不减均值、没有偏置项，少算一次归约。LLaMA、Qwen、DeepSeek 都用它。

## 版本对比

| 版本 | 做法 | 改进 |
|---|---|---|
| v0 一个线程一行 | 每个线程独自扫描一行 | 访存不合并；8192 行只有 8192 个线程，GPU 远远没有被填满 |
| v1 一个 block 一行 + 共享内存树形归约 | 线程跨步读（合并访存），平方和在共享内存里归约 | 合并访存，并行度足够 |
| v2 float4 + warp shuffle | 一次读 4 个数，归约用 shuffle | 访存指令减少为 1/4；归约只用 32 个 float 的共享内存，同步次数更少 |

## 面试高频问题

**Q1：RMSNorm 和 LayerNorm 的区别？为什么大模型用 RMSNorm？**
- LayerNorm：(x − 均值) / 标准差 · γ + β，需要两个统计量（均值和方差）。
- RMSNorm：只用均方根缩放，不减均值、不加 β。少一次归约，参数也更少；实践中效果相当，速度更快。

**Q2：算子融合在这里能做什么？**
- 推理时，RMSNorm 前面常有残差相加（x = x + residual）。把"残差相加 + RMSNorm"融合成一个 kernel，可以省掉一次把中间结果写回显存再读出来的过程。
- 这也是 go-llama-go 作业里用 Triton 做融合的思路：访存受限的小算子，融合起来收益最大。

**Q3：v2 第二遍读 x 会再访问一次显存吗？**
- 一行 4096 个 float 只有 16 KB，第二遍读取大概率命中 L1 或 L2 缓存，所以有效带宽仍然接近按"读一遍 + 写一遍"计算的值。可以用 ncu 的 `lts__t_sector_hit_rate` 指标验证。
