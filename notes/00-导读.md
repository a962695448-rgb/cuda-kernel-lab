# 导读：先建立三个直觉

这份笔记配合代码读。目标是面试时能**不看代码讲清楚**每个版本为什么更快。建议的顺序：01 SGEMM → 06 转置 → 03 Reduce → 04 Softmax → 05 RMSNorm → 02 HGEMM → 07 ncu 与 roofline。

## 直觉 1：GPU 的瓶颈要么是“算”，要么是“搬”

- **计算访存比（Arithmetic Intensity，AI）** = 浮点运算次数 ÷ 访问显存的字节数。
- 本仓库实测用的 RTX 5090：FP32 峰值约 104.8 TFLOPS，理论显存带宽 1792 GB/s（512 位总线 × 28 Gbps GDDR7），两者相除**拐点约为 58 FLOP/B**。（作为对比，RTX 4090 约为 82.6 TFLOPS、1008 GB/s，拐点约 82 FLOP/B。）
  - AI 低于拐点 → **访存受限**（memory bound），优化目标是"少搬、搬得整齐"，用 GB/s 衡量。
  - AI 高于拐点 → **计算受限**（compute bound），优化目标是"让计算单元一直有活干"，用 TFLOPS 衡量。
- 估算一下：
  - SGEMM 4096³：运算量 2×4096³ ≈ 1.37×10¹¹，最少要搬 3×4096²×4 B ≈ 201 MB，AI ≈ 683 → 计算受限。
  - Reduce：每读 4 字节只做 1 次加法，AI = 0.25 → 严重访存受限。
  - Softmax / RMSNorm：每个元素只有几次运算 → 访存受限。

这就是为什么本仓库里 GEMM 报告 GFLOPS 和 %cuBLAS，而其他算子报告 GB/s 和"占实测拷贝带宽的百分比"。

## 直觉 2：内存层次越往上越快、越小

| 层次 | 大致容量（5090） | 谁能访问 | 说明 |
|---|---|---|---|
| 寄存器 | 每个 SM 64K 个 32 位寄存器 | 单个线程 | 最快；用太多会降低 occupancy，超出上限会溢出（spill）到 local memory |
| 共享内存 / L1 | 每个 SM 最多 100 KB 共享内存（单个 block 最多 99 KB） | 同一个 block | 需要手动管理；有 32 个 bank |
| L2 | 96 MB | 全部 SM | 自动缓存 |
| 显存（GDDR7） | 32 GB | 全部 | 理论带宽 1792 GB/s，实测拷贝约 1520 GB/s；延迟几百个时钟周期 |

所有优化手段几乎都是一句话：**把数据搬到更快的层次，并且尽可能复用**。

## 直觉 3：warp 是真正的执行单位

- 32 个线程组成一个 warp，同时执行同一条指令（SIMT）。
- **合并访存**：一个 warp 访问一段连续、对齐的地址时，硬件把它合并成少量内存事务。
- **分歧（divergence）**：同一个 warp 里的线程走了不同的 if 分支，两条分支会依次执行，没走到的线程闲着。
- **warp shuffle**（`__shfl_xor_sync` 等）：同一 warp 的线程直接交换寄存器里的值，不经过共享内存。

## 学习方法

每个算子：先读笔记里的"版本对比表"，再读代码注释，然后**自己改一个参数重跑**（每篇笔记末尾都有练习）。能用自己的话把"为什么快"讲给别人听，才算掌握。
